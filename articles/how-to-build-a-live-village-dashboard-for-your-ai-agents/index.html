How to Build a Live Village Dashboard for Your AI Agents

8 October 2026 · Gary Stow, performance marketing and AI

Written by Gary Stow with help from AI tools. Every fact is checked and every article is approved by Gary before it goes live.

I run a lot of automations. One team writes and checks articles for this site, another runs three demo trading strategies, and a supervisor sits over both deciding what needs me. For months the only way to see any of it was a dashboard full of tables. It worked for me, but when my wife or my children asked what I was actually building every evening, a table of job names meant nothing to them.

So I turned the whole thing into a village. I built it to help explain my work to my family, and the visual approach made it far easier for them to understand than anything I could say. The style is a cross between RimWorld and South Park: I love playing RimWorld, and I have always been a fan of South Park.

Every page on this site is a house. Every trading strategy is a field that grows or wilts with its results. Every request walks to the Town Hall, and builders are always working on the next house. You can see the live version in the Village.

This guide shows you how to build your own, one step at a time. You do not need a game engine, and everything here is free. If you can run a Python script, you can do this.

What you need before you start

  • Python 3 on your computer
  • A text editor (I use VS Code)
  • A web browser
  • Something that already runs on its own, such as a scheduled script, an AI agent or a bot, that you want to watch
  • Optional: a free GitHub Pages website, if you want a public version people can visit

How the village works

There are only three moving parts, and keeping them separate is what makes this manageable.

  1. Your automations write a line to a log file every time they do something.
  2. A small Python script reads those logs and writes one JSON file describing the village.
  3. One HTML page reads that JSON file and draws the village on a canvas.

The drawing never talks to your automations directly. That means a bug in the village can never break the real work, and you can rebuild the picture as often as you like.

Step 1: Make every automation leave a trail

The village can only show what your automations record. Give every script one shared function that adds a line to an activity log. One line of JSON per event, called JSON Lines, is the simplest format there is, because you only ever add to the end of the file.

import json
from datetime import datetime

def log_activity(who, text, outcome="ok"):
    row = {"ts": datetime.now().strftime("%Y-%m-%d %H:%M"),
           "who": who, "text": text, "outcome": outcome}
    with open("activity_log.jsonl", "a", encoding="utf-8") as f:
        f.write(json.dumps(row) + "\n")

log_activity("writer", "Drafted: how to build a village")

Call it at the important moments: a job starting, finishing, failing, or waiting for a human.

Step 2: Decide what every building means

Before drawing anything, write down what each building stands for. This is the part that makes the village make sense to someone who has never seen your system. Mine looks like this:

  • The Town Hall is the supervisor. Every request goes through it.
  • Each team has its own district: website on one side, trading on the other. Work from one never walks into the other.
  • Houses are web pages. Bigger houses get more visits.
  • Fields are trading strategies. They all start the same size, then grow or shrink with their profit or loss.
  • People standing outside the Town Hall are requests waiting for my decision.

Keep a simple lookup from the names in your log to the building where that work happens.

Step 3: Turn the logs into one data file

Save this as village_data.py. It reads the last 48 hours of the log and writes the file the page will draw from. Run it on a schedule, or every time the page asks for it (Step 9 does that).

import json
from datetime import datetime, timedelta
from pathlib import Path

LOG = Path("activity_log.jsonl")
OUT = Path("village/village_data.json")
BUILDING_FOR = {"writer": "workshop", "checker": "hall",
                "publisher": "site", "trader": "field"}

def recent_events(hours=48):
    cutoff = datetime.now() - timedelta(hours=hours)
    events = []
    for line in LOG.read_text(encoding="utf-8").splitlines():
        e = json.loads(line)
        if datetime.strptime(e["ts"], "%Y-%m-%d %H:%M") >= cutoff:
            events.append({"time": e["ts"][11:], "from": "hall",   # every job starts at the Town Hall
                           "at": BUILDING_FOR.get(e["who"], "hall"), "text": e["text"]})
    return events[-30:]

def build(pages, results):
    data = {"generated": datetime.now().isoformat(timespec="minutes"),
            "pages": pages, "events": recent_events(), "fields": results}
    OUT.parent.mkdir(exist_ok=True)
    OUT.write_text(json.dumps(data), encoding="utf-8")

def main():
    build(pages=[{"title": "Home page", "url": "/", "views": 84}],
          results={"strategy_a": 120, "strategy_b": -40})

if __name__ == "__main__":
    main()

The page views can come from any analytics export you already have. Start with made-up numbers and swap in real ones once the picture works.

Step 4: Draw the ground with isometric tiles

The RimWorld style look comes from isometric tiles: diamonds that are twice as wide as they are tall. One small function turns a grid square into a position on the screen, and everything else is built on top of it.

const TW = 64, TH = 32;                 // one tile: 64 wide, 32 tall

function toScreen(x, y) {               // grid square -> pixel position
  return { sx: (x - y) * TW / 2, sy: (x + y) * TH / 2 };
}

function tile(ctx, x, y, colour) {
  const { sx, sy } = toScreen(x, y);
  ctx.beginPath();
  ctx.moveTo(sx, sy);
  ctx.lineTo(sx + TW / 2, sy + TH / 2);
  ctx.lineTo(sx, sy + TH);
  ctx.lineTo(sx - TW / 2, sy + TH / 2);
  ctx.closePath();
  ctx.fillStyle = colour;
  ctx.fill();
}

Loop over a grid and call tile for every square. Use one colour for grass, another for roads, and blue for a river between districts.

Step 5: Draw buildings in a paper cut-out style

A building is three shapes: a darker left wall, a lighter right wall and a roof. Thick black outlines give it the cut-out look. Draw from the back of the map to the front, sorted by x + y, so nearer buildings cover the ones behind them.

function poly(ctx, pts, fill) {
  ctx.beginPath();
  pts.forEach(([px, py], i) => i ? ctx.lineTo(px, py) : ctx.moveTo(px, py));
  ctx.closePath();
  ctx.fillStyle = fill;
  ctx.fill();
  ctx.lineWidth = 3;
  ctx.strokeStyle = "#000";
  ctx.stroke();
}

function shade(hex, pct) {              // lighten or darken a colour
  const n = parseInt(hex.slice(1), 16);
  const f = c => Math.max(0, Math.min(255, c + Math.round(2.55 * pct)));
  return "#" + [f(n >> 16), f((n >> 8) & 255), f(n & 255)]
    .map(v => v.toString(16).padStart(2, "0")).join("");
}

function box(ctx, x, y, h, colour) {    // h = height in pixels
  const { sx, sy } = toScreen(x, y);
  const top = sy - h;
  poly(ctx, [[sx - TW/2, top + TH/2], [sx, top + TH], [sx, sy + TH], [sx - TW/2, sy + TH/2]], shade(colour, -25));
  poly(ctx, [[sx, top + TH], [sx + TW/2, top + TH/2], [sx + TW/2, sy + TH/2], [sx, sy + TH]], shade(colour, -10));
  poly(ctx, [[sx, top], [sx + TW/2, top + TH/2], [sx, top + TH], [sx - TW/2, top + TH/2]], colour);
}

Add windows, doors and signs once the boxes look right. Resist the urge to make it pretty too early. Get the layout working with plain boxes first.

Step 6: Make the people walk the real work

This is the part that brings it to life. Every event in the data file sends a little person from one building to another. When the supervisor approves something, someone walks from the Town Hall to the executor. When an article goes live, a builder walks to the housing district.

const walkers = [];

function playEvent(ev) {                // ev.from and ev.at are building names
  walkers.push({ from: BUILDINGS[ev.from], to: BUILDINGS[ev.at], t: 0 });
}

function moveWalkers(dt) {              // dt = milliseconds since last frame
  for (const w of walkers) w.t = Math.min(1, w.t + dt / 4000);  // 4 seconds a trip
  for (let i = walkers.length - 1; i >= 0; i--) {
    if (walkers[i].t >= 1) walkers.splice(i, 1);
  }
}

function walkerPos(w) {
  return { x: w.from.x + (w.to.x - w.from.x) * w.t,
           y: w.from.y + (w.to.y - w.from.y) * w.t };
}

Play one event every few seconds and loop back to the start when you run out. Draw a coloured path for each team's flow, so you can see at a glance that website work and trading work never cross.

Step 7: Let the data change the world

Now connect the picture to real numbers. These two rules do most of the work in mine.

function fieldScale(net) {              // net = profit or loss in pounds
  return Math.max(0.6, Math.min(1.45, 1 + net / 400));
}

function houseFloors(views) {
  return views > 200 ? 3 : views > 50 ? 2 : 1;
}

Clamping matters. Without the limits, one great or terrible week would make a field fill the screen or vanish. Pick limits that keep the village readable.

Step 8: Run the drawing loop

Save the page as village/index.html, next to the data file, with a <canvas id="village" width="1200" height="750"> in it. Fetch the data once, then redraw about sixty times a second.

const canvas = document.getElementById("village");
const ctx = canvas.getContext("2d");
let DATA = null, last = performance.now();

function frame(now) {
  const dt = now - last;
  last = now;
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.setTransform(1, 0, 0, 1, canvas.width / 2, 80);  // grid square 0,0 sits top centre
  drawGround();
  drawBuildings();
  moveWalkers(dt);
  drawWalkers();
  requestAnimationFrame(frame);
}

fetch("village_data.json")
  .then(r => r.json())
  .then(d => { DATA = d; requestAnimationFrame(frame); });

drawGround, drawBuildings and drawWalkers are your own functions built from the pieces above.

Step 9: Serve a private version from your own computer

My private village runs from the same small Flask app as my local dashboard, so it can show everything, including the actual requests waiting for me. Clicking a person outside the Town Hall opens the decision.

from flask import Flask, send_from_directory
import village_data          # the Step 3 script

app = Flask(__name__)

@app.route("/village/")
def village():
    return send_from_directory("village", "index.html")

@app.route("/village/village_data.json")
def data():
    village_data.main()      # rebuild from the latest logs every time the page asks
    return send_from_directory("village", "village_data.json")

if __name__ == "__main__":
    app.run(port=5007)

Install Flask once with pip install flask, run the script, then open localhost:5007/village/ in your browser and you are watching your own system.

Step 10: Publish a safe public version

The public version uses the same page with a different data file. Before anything leaves my computer, a function strips out anything private. Requests become a generic title, and money is rounded.

def make_public(data):
    pub = dict(data)
    pub["requests"] = [{"id": r["id"], "from": r["from"], "title": "A decision for Gary"}
                       for r in data.get("requests", [])]
    pub["fields"] = {k: round(v / 50) * 50 for k, v in data["fields"].items()}
    return pub

A scheduled task then copies the page and the public data file into my website on a new branch, opens a pull request, and only merges it after an automatic layout check in a headless browser and an SEO checklist both pass. If either check fails, nothing goes live. I wrote about why I make automation check its own work in the independent audit.

Step 11: Make it readable for everyone

Small pixel text looks great and is impossible to read. Use a large, clear font for labels (I use Atkinson Hyperlegible, which was designed for low vision), strong contrast, and hide the smaller labels when someone zooms out so they never pile on top of each other. Test it on a phone before you share it.

What went wrong the first time

Three things caught me out, so you can skip them.

  • Labels overlapped as soon as the village grew. Showing department names only when zoomed in fixed it.
  • My first version let trading work walk into the housing district. Separate districts and separate colours for each team's flow made the picture honest.
  • My scheduled jobs run without a window, but every git command they started popped up its own black console box. On Windows, start those commands with the CREATE_NO_WINDOW flag from Python's subprocess module, or you will get a screen full of flashing windows.

Do I need to know JavaScript to build this?

No. I am self-taught and built mine with help from AI tools. You need to be able to copy code, run it, read the error when it breaks and ask for help with that error. The canvas drawing above is the only JavaScript you need.

Is it safe to show my automations in public?

Yes, if the public version gets its own data file. Never point the public page at your private data. Build a function like make_public that removes names, request details and exact money figures, and check its output before every publish.

Can I build this without paying for anything?

Yes. Python, Flask, a browser canvas, GitHub Pages and Windows Task Scheduler are all free. If you want an AI assistant in the village too, you can run one at home with no token bill, which I explain in how to build your own local AI assistant.

Why not use a game engine?

You could, but a game engine adds a lot to learn before you see anything. A single HTML page with a canvas loads anywhere, can be hosted for free and is easy for an AI assistant to help you change. Start simple and move to an engine only if you outgrow it.

Start small

You do not need eleven steps on day one. Get one building and one walking person working from a real log file. Once you see your own automation move across the screen for the first time, you will want to build the rest.
