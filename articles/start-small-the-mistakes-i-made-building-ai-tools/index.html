Start Small: The Mistakes I Made Building AI Tools

8 October 2026 · Updated 12 October 2026 · Gary Stow, performance marketing and AI

Written by Gary Stow with help from AI tools. Every fact is checked and every article is approved by Gary before it goes live.

I've made plenty of mistakes building AI tools, at work and at home. Some cost me an evening, and one cost me weeks. I wouldn't call any of it wasted, because every one of them taught me something, but if I were starting today I'd do a lot of things differently. These are the real ones.

Mistake one: letting the tool decide what I was building

At work, I set out to build twelve automations to help me manage my day job, all simple ones. Somewhere along the way, the agent I was building with went off on a tangent and started building a whole technical infrastructure behind the scenes, far beyond the simple idea I started with.

I followed it, and spent weeks of evenings, outside work hours, trying to get that build working before I realised I was chasing the wrong goals and the wrong features. I'd followed the system's lead instead of my original intent.

I did learn a lot from it, about the back-end structure, about the limits of what the system could and couldn't do, and about spotting the moment an AI starts wandering. But the lesson is simple: write down what you're actually trying to build before you start, and keep checking the work against it.

Mistake two: assuming the prompt was clear

Most of my "AI got it wrong" moments come back to the same thing, which is whether I explained the task properly and handed over enough background, or left it guessing. When it guesses, it sidetracks itself.

When my audit agent once blended two different customer groups together during a deep dive, the data underneath was fine, and the real problem was that I hadn't told it clearly which group I meant, so the fix was on my side rather than the AI's.

Mistake three: losing work that was working

The most painful lesson was a bug of my own in my trading project. My code was writing 21 columns of data into a file that only had an 18-column header. For months it quietly discarded most of that file's trading history, and nothing flagged it.

That's why I'm now strict about protecting the work:

  • document every checkpoint, so I know what "working" looked like
  • save earlier versions, so there's always something to roll back to
  • check the data, not just whether the code ran

It sounds boring, but it's the difference between a bad evening and losing months of history.

Mistake four: building things I wouldn't actually use

My social media idea tool is the clearest example, because it only worked if I was at the PC, dropping notes into one set folder in one set format, and it was dead within a week. I explain why tools like that fail for me in ADHD and AI tools, and the rule I took from it is to build around the way I actually work.

Mistake five: forgetting the ground moves

The tools keep changing under me, and more than once that's meant moving an automation to something new or rebuilding it from scratch, so these days I keep what I build simple enough to move quickly.

Mistake six: making it expensive

Early on, it's tempting to throw paid tools at every problem. Now I keep things as cheap as I can, free wherever possible, and share the work between Wade on my own PC, Claude and Copilot, so no single subscription takes all the strain. I've described how that split works on a typical night in what my evenings building with AI actually look like.

What I'd tell a marketer starting today

  1. Write down what you're building before you start, and check against it.
  2. Keep the first version small. Add to it only once it proves itself.
  3. Give the AI the context it needs, so it isn't guessing.
  4. Protect the work: checkpoints, old files, and checks on the data itself.
  5. Build around how you actually work, or you won't use it.
  6. Expect to rebuild. The tools will change.
