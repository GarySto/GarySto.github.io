Coding with AI as a Non-Developer: How I Check What I Can't Write

14 November 2026 · Gary Stow, performance marketing and AI

Written by Gary Stow with help from AI tools. Every fact is checked and every article is approved by Gary before it goes live.

Coding with AI as a non-developer means the AI writes the code while you decide what it should do and check whether it actually works. I'm not a developer and I won't pretend to be, but everything on this website, and the automation teams that run behind it, was built that way. The part nobody tells you about is the checking, so that's what this piece is about.

How I check code I can't write

I can't check code I couldn't have written, and I won't pretend otherwise. What I can do is apply the same principle I use for everything AI produces, which is to ask for an independent audit. A fresh pass looks for mistakes, issues and breaks, and then they get corrected before anything is used.

That habit matters more with code than with anything else, because broken code can look perfectly confident. A paragraph with a mistake in it usually reads oddly. A script with a mistake in it can look exactly like one that works. I go into the habit itself in the independent audit: why I make AI check its own work.

The bug that cost me a whole session

My most frustrating bug was only a few weeks ago. Claude told me it had found a problem in my system, and we spent a whole session building the solution, only to realise at the very end that the solution already existed, because it had never been a problem in the first place. Claude hadn't checked the right folder, possibly because that folder wasn't linked to it, so the whole session was wasted on something that was already there.

The lesson I took from it is to look before you build. When something tells you there's a problem, check what already exists first, because the alarm can be right about the symptom and wrong about what's needed. It's an easy mistake to make when you can't read the code yourself, because the AI's explanation is the only map you have.

What I wish I'd known about GitHub

I wish there had been an idiot's guide to GitHub when I started. I didn't realise how valuable it was, what GitHub Actions could cost, or where the limits were, and I found all three out by running into them.

Since then I've shown a lot of people that you can host a website on GitHub, including people with their own businesses who now save on hosting fees. Even some experienced GitHub users I showed didn't know. I'm definitely not the man to write that idiot's guide, because I'm making this up as I go along, but that's rather the point. You don't need to know everything before you start.

Act like a project manager

The biggest shift for me is that coding with AI as a non-developer means acting more as a project manager than anything else. You validate the outputs, not the how. What matters is what exists afterwards, and you check everything the same way you would if you were managing a project or a team. You might not be the specialist, but you know what you expect at the very end, and that's the standard you hold the work to.

What a non-developer needs instead of coding skills

If you can't write code, these are the things that matter more than learning syntax:

  • Knowing what you want it to do. The AI can write the code, but it can't decide what the tool is for.
  • Asking for the independent audit on anything you're going to rely on.
  • Looking before you build, so you don't spend an evening fixing something that was never broken.
  • Being honest about what you don't know, to yourself and to anyone you show the work to.

Where I'd start

Pick one small, real problem you have, and ask an AI to build the simplest thing that solves it. Ask it to explain each step in plain English, then ask a fresh chat to audit what it built before you use it.
